# Seed 555 verification

This folder contains the [complete baseline and resilient episode output](seed-555.json) generated by the code on the `demo-render` branch. It is a static fallback when the free Render service is asleep.

## Claims in the Day 1 video

| Video claim | Check in the trace |
| --- | --- |
| 30 ticks / 90 actions per policy | `baseline.ticks`, `resilient.ticks`, and the length of each `log` array |
| Same seed and attack sequence | Both `seed` values are 555; compare attacker entries in both logs |
| Tick 06: limit becomes $100 | Attacker `launch_attack` parameters under tick 6 show `max_amount: 100` |
| Baseline attempts $500 and billing rejects it | Baseline worker `issue_refund` under tick 6 has `amount: 500` and `result.success: false` with the rejection text |
| Auditor flags the attempt | Baseline oversight action under tick 6 is `flag` with `flag: true` |
| Resilient policy checks the limit | Resilient worker action under tick 6 is `get_current_policy` and its result shows the $100 limit |
| Worker reward 17 versus 26 | `baseline.scores.worker` and `resilient.scores.worker` |
| Seven flags versus zero | `baseline.metrics.total_flags` and `resilient.metrics.total_flags` |
| Reported oversight accuracy 86.7% versus 100% | `baseline.metrics.oversight_accuracy` and `resilient.metrics.oversight_accuracy` |

To regenerate locally from this branch, install the project dependencies and run:

```bash
.venv/bin/python - <<'PY'
from sentinelops_arena.web import simulate
for policy in ("baseline", "resilient"):
    result = simulate(555, policy)
    print(policy, result["scores"], result["metrics"])
    print([entry for entry in result["log"] if entry["tick"] == 6])
PY
```

The metric percentages are simulator reward proxies, not production outcomes. The policies are handwritten heuristics. The resilient policy checks the refund limit but does not complete that refund. No money moves.
